# vnmap

[![R-CMD-check](https://github.com/ura8107/vnmap/actions/workflows/R-CMD-check.yaml/badge.svg)](https://github.com/ura8107/vnmap/actions/workflows/R-CMD-check.yaml)

`vnmap` makes publication-ready choropleth maps of Viet Nam in R. It follows
the compact API of [`usmap`](https://usmap.dev), while accounting for Viet
Nam's July 2025 administrative reform.

## Installation

Install the current development version directly from GitHub with either
`remotes` or `pak`:

```r
# Using remotes
install.packages("remotes")
remotes::install_github("ura8107/vnmap")

# Or, using pak
install.packages("pak")
pak::pkg_install("ura8107/vnmap")
```

The repository must be public for anonymous installation. For a private
repository, set a GitHub personal access token before installation, for
example with `Sys.setenv(GITHUB_PAT = "...")`.

## Quick start

```r
library(vnmap)
library(ggplot2)

plot_vnmap()

example <- data.frame(
  province = province_info()$name_en,
  value = seq_len(34)
)

plot_vnmap(data = example, values = "value", id = "province",
           color = "white", linewidth = 0.2) +
  scale_fill_viridis_c()
```

Current commune boundaries use the same province identifiers and carry an
explicit geography vintage:

```r
hanoi_communes <- vn_map("communes", province = "Ha Noi")
```

Use the NSO-published reform workbook when joining pre-July-2025 commune data. A
former unit may map to multiple current units where its territory was divided;
`relation == "part"` records that fact, but no unpublished allocation weights
are inferred. The workbook is downloaded explicitly because its redistribution
terms have not been established; it is not bundled with `vnmap`.

```r
path <- download_administrative_crosswalk(tempfile(fileext = ".xlsx"))
administrative_crosswalk(path, current = "00004")
administrative_crosswalk(path, province = "Ha Noi")
```

Transport facilities can be queried and layered in the same way:

```r
infrastructure(type = "aerodrome", province = "Ha Noi")

plot_vnmap() + geom_infrastructure(type = c("port", "aerodrome"))
```

The snapshot contains 42 aerodrome entities, 80 named OSM industrial-port
features, 32 border-control entities, and nationwide OSM trunk-network
segments. Categories are deliberately conservative: `aerodrome` does not mean
scheduled commercial service and `port` does not mean seaport. Use
`infrastructure_class`, `service_type`, `facility_roles`, and `status_source`
before constructing access or treatment variables. All data are community
mapping rather than an official register.
Network lines are generalized to 100 metres and are intended for statistical
accessibility analysis and graphics, not routing or navigation.
Railway yards, sidings, spurs and industrial lines are separately classified,
and line features use `province_codes` for actual polygon intersections rather
than a fabricated single-province owner.

The package also includes official 2024 population and regional-economic
indicators. This produces a GRDP-per-capita choropleth for the current units:

```r
data(province_stats_2024)

plot_vnmap(
  data = province_stats_2024,
  values = "grdp_per_capita_million_vnd",
  id = "code",
  color = "white",
  linewidth = 0.2
) +
  scale_fill_viridis_c(name = "Million VND\nper person")
```

## Administrative geographies

The current 34-unit geography is the default. The 63-unit geography used
immediately before 1 July 2025 remains available for historical data.

```r
vn_map()                              # 34 current units as an sf object
vn_map("provinces_63")               # historical 63-unit geography
plot_vnmap(include = c("Hà Nội", "Bac Ninh"))
province_code(c("Đà Nẵng", "Da Nang", "Danang"))
province_info("79")
```

Identifiers accept official two-digit administrative codes and names with or
without Vietnamese diacritics. `province_info()` provides a clean join table.

## Socio-economic regions

Every unit is tagged with one of the six General Statistics Office
socio-economic regions. Select whole regions with `region`, or look the region
up directly.

```r
plot_vnmap(region = "MRD", labels = TRUE)   # Mekong River Delta
province_region(c("HCMC", "Can Tho"))
province_info()[c("name_en", "region_code", "region_en")]
```

## Lower-level geographies

Optional historical district (`"districts_63"`) and commune (`"communes_63"`)
layers cover the pre-July 2025 second and third administrative levels, which
the reform abolished and merged. They are large, so they are not bundled;
generate them locally with `data-raw/build_adm2.R` and `data-raw/build_adm3.R`,
then filter to a province. Commune names are not unique nationwide, so always
scope commune maps with `province`.

```r
# after Rscript data-raw/build_adm3.R
vn_map("communes_63", province = "Ha Noi")
```

## Working without sf

The name, code, and region lookups (`province_code()`, `province_info()`,
`province_region()`) and the bundled statistics work without the `sf` package.
Only the geometry functions (`vn_map()`, `plot_vnmap()`, `vnmap_crs()`) require
`sf`.

## Industrial parks

The bundled registry holds one row per industrial park, keyed to the current
34-unit provinces, the pre-2025 63-unit provinces, and the current communes. It
can be filtered using current or former province names and added directly to an
ordinary `ggplot2` map:

```r
industrial_parks(province = "Dong Nai", geometry = "point")

plot_vnmap(include = "Dong Nai", color = "white") +
  geom_industrial_parks(province = "Dong Nai")
```

`industrial_park_registry()` returns the same records as a plain data frame with
`lon`/`lat` columns and no `sf` requirement, which is the convenient form for
joining an external list of parks on `park_key` or on the administrative codes.

```r
registry <- industrial_park_registry(province = "Dong Nai")
registry[c("id", "name_vi", "commune_name", "area_ha", "location_accuracy")]
```

Parks that OpenStreetMap has drawn are returned as polygons with
`location_accuracy = "site"`. Parks that it only names - through an entrance
gate, a bus stop, an internal road or a plant inside them - are still recorded,
placed at the centre of those references with `location_accuracy = "locality"`
and no `area_ha`. Filter with `accuracy = "site"` when a boundary is required.
Every row carries the contributing OpenStreetMap elements in `osm_refs`.

The registry is intentionally conservative: a park enters it only where a
redistributable mapped location exists, so it is smaller than the government's
legal register and unevenly complete across provinces.
`industrial_park_coverage()` states that gap rather than leaving it implied.

```r
head(industrial_park_coverage())
industrial_park_coverage("national")
```

The national comparison is made against the Foreign Investment Agency (Ministry
of Finance) count of 478 established industrial parks as of 30 September 2025.
This is a mapping snapshot, not a substitute for the legal register.

## Economic and policy zones

`economic_zones()` provides a deliberately conservative, evidence-graded
snapshot of coastal and border-gate economic zones, export-processing zones,
and named high-tech parks. Legal document numbers, dates, and direct official
URLs are retained only where verified; missing row-level evidence remains
explicit. Point accuracy is recorded for every row.

```r
economic_zones(type = "national_high_tech_park")
plot_vnmap() + geom_economic_zones(type = "coastal_economic_zone")
```

The snapshot retains 20 coastal and 26 border-gate catalogue records matching
current officially reported aggregate counts. Names without verified row-level
instruments are labelled `candidate_or_count_reconciled`, not established. It
also retains three named high-tech parks without claiming national completeness,
and the three EPZs in the current Ho Chi Minh City official annex. The EPZ
population is subnational and must not be described as a national register.
Where no reusable zone geometry was verified, the record is retained at a
deterministic pre-2025 province interior point with
`location_accuracy = "province_only"` and `geometry_available = FALSE`.
Industrial parks remain separate even when they lie inside an economic zone.

## Data provenance

The historical 63-province geometry is derived from the public-domain
[geoBoundaries VNM ADM1 release](https://www.geoboundaries.org/). Current
communes come from a pinned MIT-licensed community dataset derived upstream
from Viet Nam's Administrative Units Reference Map; current province polygons
are dissolved from those exact commune polygons. Both are generalized for
statistical plotting and are not legal-boundary products. The
[`data-raw/`](https://github.com/ura8107/vnmap/tree/main/data-raw) directory
contains the complete reproducible build.

`province_stats_2024_63` contains official 2024 area, average population,
population density, and preliminary GRDP per capita from Viet Nam's General
Statistics Office PX-Web. `province_stats_2024` aggregates those values to the
current 34 units: population and area are summed, density is recalculated, and
GRDP per capita is population-weighted. The source values are rounded, so
aggregated results are estimates. Run `Rscript data-raw/fetch_nso_stats.R` to
refresh the statistical datasets from the official tables.

The industrial-park registry is derived from a pinned OpenStreetMap Overpass
snapshot observed 11 August 2026 and used under ODbL 1.0; each record names the
contributing elements in `osm_refs`. Its coverage is measured against the
Foreign Investment Agency (Ministry of Finance) national totals as of
30 September 2025, which are bundled as counts and areas only, with no park
list or geometry taken from that source.

The historical source vintage is 2008; the current source is an observed
25 July 2026 snapshot. Always select the geography matching the data period.
